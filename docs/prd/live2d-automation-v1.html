Product Requirements Document · v1.1 · 增量更新

Live2D 链路增量更新：接上「可导入」的交接点

本次更新不重建链路。分割、合成、网格、骨骼、参数、物理、moc3 导出都已在仓里跑通； 要做的是把已有能力的接缝补齐——层名对齐、掩码交接、PSD 承载、证据分级—— 让产物能被 Live2D Cubism 一次导入并继续绑定。

性质 增量 · 接缝补齐 复用 既有分割/网格/物理链路 主用户 Live2D 绑定师 状态 待评审

1. 背景：这次更新要解决什么

链路今天已经能跑到「切出 29 个语义图层」并算出每个部件的像素网格、关节拆分与覆盖率 （实测一张 600×900 立绘：37 个绑定部件、12509 顶点、119812 个角色像素 100% 被网格覆盖）。 但只要把产物往 Live2D 那边推，就会在三个具体接缝上停住：

接缝一：层名对不上，骨骼接不上

分层产出 thigh_L / shin_L / arm_L / eyebrow_L， 而骨骼映射表里写的是 thigh_left / calf_left / upper_arm_back_left / eyebrow_l。 自动挂骨目前命中不到任何一个新层。

接缝二：掩码在合成后就被丢了

绑定管线里 part_masks 是个从未被读取的空参数；网格只能从 PNG 的 alpha 反推。 分割阶段算出的高质量掩码没有进入绑定阶段。

接缝三：交付物是 PNG 包，不是 Cubism 能吃的入口

Cubism 的官方建模入口只有一个：导入 PSD，图层自动变成 ArtMesh。 现有 PSD 生成是平铺图层、无分组、不校验 sRGB/位深，无法承担「按部件树导入」这件事。

为什么必须走 PSD，而不是「直接写工程文件」 官方「外部应用集成 API」的全部指令是：注册插件、读写参数值、读参数与参数组、读文档与当前模型、 读当前编辑模式、读物理 FPS、写日志，以及四类导出完成通知。 没有任何指令能创建 ArtMesh、设置网格顶点、创建变形器、创建参数或关键形状，也没有保存工程的指令。 参见 官方指令表。 官方 Core 只提供读取 .moc3 的接口，.cmo3 是 Editor 的工程格式且无公开规范（见 文件类型 与 Core API）。 所以「一键生成可编辑工程」在官方路径上不成立，PSD 是唯一合法交接点。

3. 变更范围

P0：把三个接缝接上

原画→ 语义分层→ 部件拆分→ 关节段接入→ 掩码交接→ PSD 自检→ 导入 Cubism→ 绑定规格→ 验收报告

蓝＝已有可直接用；绿＝本次新增/补齐；红＝产品边界（人来做）。

类型内容受影响模块
复用语义分层、图层合成、部件拆分算法、质量门检查项、骨骼/变形器结构、参数表、物理摆动组、moc3 导出不改动
增强关节段与发段接入绑定管线；掩码显式传递；PSD 改为分组构建并加硬约束校验；层名与骨骼映射对齐；质量门口径对齐证据分级绑定管线、PSD 生成、骨骼映射、质量门
新增分层计划与补绘审核记录；PSD 重开自检；证据分级与作品状态机；交付物清单本次新增环节

P1：可选

  • 网格键形自动烘焙（依赖自建 moc3 链路，须先解决已知内核不稳定问题）。
  • 眼白/瞳孔/高光/上下睫毛进一步细分；嘴型多态（mouth_a/i/u/e/o）。
  • 多视角设定图驱动同一套部件的形变参考。

边界不变量（不因本次更新而改变）

  • 不宣称、不暗示「导入 Editor 后自动完成建模」。
  • 不把 AI 补绘直接标为高质量完成。
  • 不为了增加图层数量而过度拆分；不需要独立运动的细节必须合并。

4. 目标与完成判据

每条都能直接观察，不需要推断：

  • 绑定师拿到的 PSD 一次导入成功，图层结构直接映射成部件树，不出现导入报错或图层丢失。
  • 每个部件的层名都能在骨骼映射里命中，关节段（上臂→前臂、大腿→小腿）自动形成父子链。
  • 每个部件都带有网格规格（顶点/三角形/覆盖率），且覆盖率可复算为 100%。
  • 报告里每一条「通过」都挂着证据等级；缺证据的项显示为缺口而不是通过。

5. 功能需求

FR-01

分层计划与补绘审核

新增

现在分层是「直接跑」，跑完才知道少了什么。补一层前置计划，把返工挡在前面。

变更点
在分割之前插入「计划 → 确认」环节。计划内容：部件清单（名称、分组、遮挡序、是否需要补绘）、 用户声明的动作需求映射、合并/独立判定及理由。 补绘区域产出补绘记录，状态为 待审核 / 已审核 / 驳回。
规则
多视角设定图必须指定主视角，其余仅作补绘参考，不得混入同一画布。 状态为 待审核 的补绘，不允许作品进入「素材分层完成」。 缺少必要部位且无法补绘时，标 缺失·不可补绘 并说明哪些动作将无法实现。
结果
计划被确认后才进入分割；补绘记录随交付物一并输出。
例外
补绘与周围线稿/明暗接不上时降级为 驳回 并保留原始空洞，由绑定师决定是否接受。
FR-02

关节段与发段接入绑定链路

增强

拆分算法已经能按关节切、按段切，但结果没有进入绑定管线，等于白算。

变更点
把「按关节拆分（上臂/前臂、大腿/小腿）+ 头发分段」接进绑定管线的层名入口， 并让每一段带上 枢轴（pivot） 与 关节（joint） 坐标。 关节段的父级必须是它的近端段。
规则
拆分必须像素守恒：拆分前后像素数一致，段与段之间不重叠。 部件过小或切出空段时保留整块并记录原因，不得强行拆成碎片。 头发分段固定「自上而下」，第 1 段必须是最靠近发根的一段。
结果
绑定管线拿到的是关节段而不是整条手臂；骨骼链可直接建立。
例外
拆分后某段像素低于下限时合并回原型并标注，不得保留不可用的碎片段。
FR-03

掩码显式交接

增强

分割算出的掩码在合成后就丢了，绑定阶段只能从 PNG 的 alpha 反推，精度与信息都退化。

变更点
把部件的布尔掩码从分层阶段显式传给绑定阶段，使网格基于掩码而不是 alpha 重建。 同时保留「仅有 PNG 时」的降级路径，并标注本次用的是掩码还是 alpha。
规则
掩码与图层必须同尺寸、同数量、同名；不一致时阻断并列出差异项，不得静默重建。
结果
网格输入来源在交付物中可追溯（mask / alpha）。
FR-04

层名与骨骼映射对齐

增强

命名两套并存，自动挂骨命中不到任何新层——这是当前最直接的断点。

变更点
建立唯一的命名口径并让骨骼映射、网格规格、PSD 图层名三者共用： 部位名 + 侧别后缀（_L / _R）；关节段固定为 upper_arm_* / forearm_* / thigh_* / shin_*。 映射表补齐新层名，并为历史别名保留兼容映射。
规则
任一部件名无法映射到骨骼时，必须报缺口而不是静默挂到默认骨骼。 同名冲突自动加侧别或序号后缀，并同步更新所有下游清单。
结果
每个部件都能回答「我挂在哪根骨骼上」；映射覆盖率为 100% 或明确列出未覆盖项。
FR-05

分组 PSD 构建

增强

把「平铺图层 PSD」升级成「按部件树组织的导入用 PSD」。这是整个更新最关键的一次交接。

硬约束（任一不满足即导入失败或改色，全部来自官方）
  1. 保存格式必须是 PSD
  2. 色彩模式必须是 RGB
  3. 通道必须 8bit/channel
  4. 色彩配置必须 sRGB
  5. 不得有同名图层
  6. 不得使用图层蒙版
  7. 线稿与剪切蒙版必须合并
  8. 每组最底层图层作为纹理，故线稿层与填色层须预先合并
  9. 图层属性须能对应 Editor 的 Color blend
  10. Opacity 会生效，但 Fill 按 100% 输出

来源：Notes on PSD creation · Import PSDs

变更点
在现有 PSD 生成上补三件事：① 按分组建立多层组结构（组可嵌套），每个部件在组内是单一图层； ② 显式写入 RGB / 8bit / sRGB 并校验；③ 构建前做同名检测与线稿/填色合并检查。 图层顺序即遮挡顺序，与分层阶段的 z 序一致。
参考层的处理（易踩坑）
官方明确「PSD 中隐藏的图层与组也会被导入」。因此原图参考层不能放进导入用 PSD， 否则会变成一张占满画布的 ArtMesh。参考图只能：① 作为独立文件随包； ② 走「重新导入 → 仅注册 PSD、不添加 ArtMesh」；③ 作为「原图/模型导引图」。 白色背景参考层同理。
结果
一份导入用 PSD + 图层清单（图层名、分组路径、画布偏移、像素数、遮挡序、对应部件）。
例外
硬约束任一不满足 → 标记 不可导入 并阻断交付，列出具体违规项，不做「先交后修」。
FR-06

PSD 重开自检

新增

在交出去之前，先自己当一次 Cubism。

变更点
三项必查：① 重新打开 PSD 并逐层核对与图层清单一致（数量、名称、分组、尺寸、偏移）； ② 复查硬约束（格式/位深/色彩模式/同名/蒙版/Fill 与 Opacity）； ③ 按遮挡序合成各层并与原画比对。
规则
合成差异必须区分来源：「补绘露出的合理差异」与「分割/组装错误导致的差异」分开列， 不得用一个总相似度掩盖后者。
结果
通过的 PSD 标 可导入；否则 不可导入 并阻断。
FR-07

网格规格与覆盖率

增强

网格已经能算，本次要做的是把「覆盖率」变成交付物里的硬指标，并说明它怎么用。

变更点
每个部件产出一条网格规格：顶点数、三角形数、覆盖率、外框比（网格面积 ÷ 部件面积）。 覆盖率要求：部件内每个不透明像素都落在某个三角形内，未覆盖数为 0。
用法（必须写清，避免误解）
Editor 导入时会用自己的自动网格（最少顶点 + 1px 内边距）。本规格的用途是： ① 绑定师替换自动网格时的目标；② 自检 Editor 网格密度是否够用； ③ 自建 moc3 链路的输入。它不是「导入即生效」的东西。
例外
轮廓里不属于任何部件但确实属于角色的像素（色块接缝、外轮廓暗边）必须收进残差层 并如实报告占比，不得静默丢弃后宣称 100%。
FR-08

变形器层级与参数规格

增强

参数表已经完整，缺的是「层级说清楚」和「参数到底驱不驱动」的区分。

变更点
① 为每个部件指定所属变形器、类型（warp 管形变 / rotation 管旋转）与父子关系，并写明 控制目标；校验无环、无孤立部件、关节父子链完整。 ② 参数规格沿用现有 14 项标准参数，补上「关键形状是否存在」这一状态： 只有形状被实际制作并可观测到形变才标 已生效，否则保持 仅声明。
禁止项
不得把变形器当三维骨骼设计。Live2D 的核心是二维网格 + 变形器 + 参数 + 关键形状。
结果
变形器树 + 挂载关系 + 参数状态表；「参数存在」与「参数有用」在报告里是两个字段。
FR-09

物理配置补齐

增强

摆动组已能产 physics3.json，本次只补缺的类别与顺序约束。

变更点
制作顺序固定：后发 → 侧发与发梢 → 飘带 → 耳饰与链条 → 裙摆与服装。 补齐飘带与链条/耳饰的显式摆动组；绑定的部件改用关节段/发段后的新层名。
规则
先完成基础变形再启用物理。每个摆动组必须声明输入参数、输出参数与适用部件； 越长的发束摆幅与延迟越大。
验收判据（可观测）
不得出现：持续抖动、部件漂浮、明显穿模、无法回归默认位置。 数值容差 TBD，由验收人按角色幅度确认。
FR-10

证据分级

增强

质量门已有检查项，但「通过」没有等级，容易被读成「模型能动了」。

变更点
复用现有检查项，把结论映射成三级证据： E0 机器已验（覆盖率、像素守恒、图层清单一致、硬约束、层级无环）／ E1 内核已验（官方内核可加载 + 参数变化产生预期形变）／ E2 人工已签核（补绘可接受、观感像原画、物理手感自然）。
规则
E2 只能由人给出，产品不得代签。同一份报告不得出现「E2 未做但整体通过」。 环境不具备官方内核时，E1 标 未验证·环境缺失，不得因 CI 全绿推断通过。
必测项
原始姿势合成、头部左右转、抬头低头、头部倾斜、眼球移动、眨眼、嘴部开合、表情切换、 身体倾斜、手臂运动、头发与饰品物理、裙摆与飘带运动。每项输出结果 + 问题清单。
FR-11

交付物与作品状态机

新增

让任何人拿到产物就能判断它处在哪一步、还差什么。

交付物
① 导入用 PSD；② 图层清单与网格规格；③ 独立部件 PNG（带偏移）；④ 变形器/参数/物理规格； ⑤ physics3.json；⑥ 分层计划与补绘记录；⑦ 验收报告；⑧ 预览图。 可编辑工程（.cmo3）不在默认交付物内。
状态机
已受理 → 已规划 → 已分割 → 已补绘待审 → 素材分层完成 → 已导入 → 绑定中 → 绑定完成。 每次跃迁必须有对应证据；缺证据时停在原状态并给出缺口清单。
两个完成态
素材分层完成 = PSD 自检通过 + 补绘全部 已审核 + 网格覆盖率 100% + 骨骼映射 100%。
绑定完成 = E0 全部通过 + E1 全部通过 + E2 全部签核。
禁止项
不得把空图层模板、原图复制层、未补绘的拆分图、未经验证的 PSD 声称为完整可动的 Live2D 成品。 降级产出必须显式标注原因。

6. 受影响的既有规则

本次更新会动到四条已经被下游依赖的规则，必须一次性改齐，避免出现两套口径。

规则现状更新后
命名 分层层名与骨骼映射表各用一套（shin_L vs calf_left） 唯一口径 = 部位名 + 侧别后缀；关节段固定前缀；历史别名保留兼容映射
掩码传递 合成后丢弃，绑定阶段从 alpha 反推 显式传递并标注来源（mask / alpha）；不一致即阻断
PSD 生成 平铺图层，无分组，不校验位深与色彩配置 分组构建 + 硬约束校验 + 同名检测 + 重开自检
「通过」的含义 质量门给出缺陷数，达不到门槛只记录不阻断 结论必须挂 E0/E1/E2 等级；E2 未签核不得整体判通过

坐标与降级（沿用既有约定）

  • 全作品统一画布与原点；裁切必须记录偏移（偏移为 0 也要记），任何改变位置的步骤都要重跑复位校验。
  • 降级必须显式：补绘不可用 → 保留空洞并标 缺失·不可补绘；官方内核不可用 → E1 标 未验证·环境缺失；PSD 硬约束不满足 → 不可导入。

7. 开放问题

问题为什么现在定不了影响
目标画布尺寸与 DPI 是否强制 4096×5120 / 350dpi？ 参考图给出的是这组值，但未确认是「本作品要求」还是「示例」。它直接影响网格密度与纹理页数。 FR-05、FR-07
网格默认密度取多少？ 密度是「形变精度」与「顶点数」的权衡，需绑定师按动作幅度确认；目前只在一张 demo 上验证过一组参数。 FR-07
物理手感是否单列为一项签核？ 手感偏主观，是否单独作为一条 E2 需要与审核流程对齐。 FR-09、FR-10
是否接受自建 .moc3 编译作为「绑定完成」的合法路径？ 该路径能绕开 Editor 手工操作，但存在已知的内核加载不稳定问题；是否纳入 P1 取决于风险偏好。 §2、FR-08
