Product Requirements · Pygmalion Studio

双模式图像生成：用户自接 API 与本地算法生成

让同一条「生成 → 分层 → 绑定 → 导出」主链路，既能由用户自己的图像服务驱动， 也能在完全离线、无任何大模型的情况下跑通，并保持产物结构一致。

状态：待评审 版本：0.1（草案） 日期：2026-10-19 范围：新模块 / 中高复杂度

1. 背景与目标

观察到的现状

  • 生成页当前只有一个「Generate」按钮，用户无法选择、也无法接入自己的图像服务；后端其实已有可路由的上游集合（seedream、sensenova、openai 兼容、pollinations、local_placeholder），但产品界面没有暴露。
  • 完全离线时，唯一能出图的是「本地占位图」：只有渐变、剪影和提示词水印，不是可用的人物立绘，更不产出分层。
  • 用户在实际验收中已经遇到「生成成功但图片不显示」的情况。该问题属于产物目录与静态服务目录不一致的缺陷，已单独修复，不属于本 PRD 范围。

产品判断

用户真正要的不是「更多模型选项」，而是一条永远能走通、且产物结构一致的出图路径： 有 Key 的人希望用自己已经付费的服务；没有 Key、没有网络、或不愿把提示词发出去的人， 希望本机也能产出一套可以继续分层和绑定的素材。

目标（可观察结果）

  • 用户可以在应用内配置一个自己的图像服务，并在生成时明确知道「本次由谁出图」。
  • 在无网络、无 Key 的机器上，用户仍能得到一套分层的人物素材，并继续完成分层、导出、预览。
  • 两种模式产出的结果对象结构一致，下游页面不需要为「模式」写分支逻辑。

2. 范围

P0（首次可用必须完成）

  • 生成模式选择：自接 API / 本地算法。
  • 自接 API 的配置、连接测试、生成与失败提示。
  • 本地算法生成：参数面板、确定性出图、分层产物与清单。
  • 两种模式共用同一份结果契约与同一套错误语义。

P1（后续增强）

  • 多套 Provider 配置档案与快速切换。
  • 用一张参考图提取配色，作为本地算法的输入。
  • 算法模式的风格预设（校园 / 奇幻 / 日常）。

明确不做

  • 不做内置模型下载与权重管理。
  • 不做云端账号体系、额度计费、团队共享 Key。
  • 不在模式失败时静默替换成另一种模式。

3. 产品模型

模式（Mode）

api：由用户配置的外部图像服务出图。
algorithmic：由本机程序按参数绘制，不调用任何模型或网络。

生成配置（GenerationProfile）

一次生成所使用的完整输入：模式、提示词、尺寸、随机种子、可选的角色一致性参数， 以及（仅 API 模式）所选的 Provider。

结果（GenerationResult）

两种模式必须产出同一结构：主图地址、实际使用的来源标识、分层列表、可选的清单文件地址。 来源标识用于在界面上如实标注「谁生成的」。

Provider

一个可被调用的外部图像服务实例：显示名、协议类型、服务地址、模型名、密钥（可空）、 当前可用状态。密钥只属于本机。

4. 功能需求

FR-01 生成模式选择 P0

项定义
目的让用户在发起生成前明确本次使用哪条出图路径。
位置生成页主表单顶部，位于提示词输入框之前。
触发进入生成页时读取上次使用的模式；用户可随时切换。
处理规则 选择 自接 API 时，若没有任何可用 Provider，主按钮置灰并给出「去配置」入口；
选择 本地算法 时，隐藏 Provider 相关控件，显示算法参数面板。
结果与状态当前模式在生成按钮上方持续可见；切换模式不自动清空提示词。

FR-02 Provider 配置 P0

项定义
目的让用户接入自己已经拥有的图像服务。
入口新增「设置 → 图像生成」；生成页的「去配置」直接跳转此处。
字段 显示名（必填，本机唯一）、协议类型（OpenAI 兼容 / 内置供应商）、服务地址（协议类型为兼容时必填）、 模型名、密钥（可空）、是否设为默认。
处理规则 保存前校验地址格式与本机唯一性；密钥输入框默认掩码，仅在用户点击「显示」时明文；
保存后立即进入「未验证」状态，必须由用户主动测试连接后才变为「可用」。
结果与状态Provider 生命周期：未验证 → 可用 / 不可用；用户可编辑、删除、设为默认。
例外删除正在被默认引用的 Provider 时，要求用户先指定新的默认，或明确选择「暂无默认」。

FR-03 连接测试与状态 P0

项定义
目的把「Key 写错了」和「服务挂了」在发起生成前就区分开。
触发用户点击「测试连接」。
处理规则发起一次最小代价的探测请求；超时上限固定，不阻塞界面；同一 Provider 进行中不可重复触发。
结果与状态 成功：显示「可用」与耗时；
失败：显示可读原因分类（鉴权失败 / 地址不可达 / 限流 / 超时 / 服务端错误），并保留用户已填内容。

FR-04 自动路由与回退 P0

项定义
目的在用户未指定 Provider 时仍能出图，同时不隐瞒真实来源。
处理规则 用户指定了 Provider：只调用该 Provider，失败即失败，不回退。
用户未指定：按「默认 Provider → 其余可用 Provider」顺序尝试；
全部失败时不自动切到本地算法，而是提示两条明确选项：「改用本地算法重试」或「返回检查配置」。
结果与状态结果面板必须显示「本次来源」，回退发生时追加一行「已从 X 回退到 Y」。
例外用户取消生成后，不得继续尝试后续 Provider。

FR-05 生成执行与结果回执 P0

项定义
目的让用户知道「已经生成好了」，并能立刻继续下一步。
处理规则 生成期间展示分阶段进度与可取消入口；任一阶段失败，保留已完成阶段的产物可见。
结果与状态 成功：主图、来源标识、分层数量、可用的下一步操作（保存 / 去分层 / 送去 Live2D）。
失败：错误分类、可重试入口、模式与 Provider 保持原选择。
边界主图加载失败时必须显示明确失败态与「重新加载」，不得留下空白区域或只显示替代文本。

FR-06 本地算法生成参数 P0

项定义
目的在无模型、无网络条件下，产出一套可控且可复现的人物素材。
参数 体型比例、发型、发色、瞳色、肤色、服装款式与主色、配饰、表情、视角、随机种子、输出尺寸。
处理规则 相同参数 + 相同种子必须产出相同结果；参数变化只影响对应部位，不重绘整张图；
所有绘制在本地完成，不发起任何网络请求。
结果与状态生成结果必须标注「本地算法生成（非 AI 模型）」；界面提供「换一个种子」快捷操作。
边界参数组合超出支持范围时，在生成前就地提示，不进入生成流程。

FR-07 分层产物与清单 P0

项定义
目的让算法模式的结果可以直接进入分层、绑定、导出，而不是一张死图。
产物 背景、后发、身体、服装、面部、眼睛、前发、配饰，各自独立透明背景图片；
一份清单，记录图层顺序、每层用途、画布尺寸与对齐基准点。
处理规则图层命名与顺序遵循与现有分层结果相同的约定，使下游无需按模式分支。
结果与状态图层页可直接打开该结果并逐层预览；缺失任一必需图层时，结果标记为「分层不完整」并说明缺哪层。
例外输出目录不可写时，生成失败并提示路径与原因，不产出半套文件。

FR-08 失败与边界 P0

场景产品行为
无可用 ProviderAPI 模式主按钮置灰，展示「去配置」与「改用本地算法」两个入口。
密钥无效提示鉴权失败，聚焦到密钥字段，不自动重试。
网络不可达提示不可达并给出「改用本地算法」入口。
限流提示稍后重试，展示建议等待时长（若服务返回）。
生成超时允许取消；取消后不写入历史，不更新「最近一次生成」。
磁盘不可写生成前预检并阻止，提示产物目录与解决办法。

5. 共享规则

5.1 密钥与隐私

  • 密钥只保存在本机，不上传、不写入日志、不出现在诊断信息中。
  • 界面与导出内容中密钥一律掩码显示。
  • 本地算法模式不发起任何网络请求，提示词与参数不出本机。
  • 发送给外部服务的内容仅限提示词、尺寸与必要的生成参数。

5.2 来源标注

  • 每条结果都必须带来源标识，并在结果面板可见。
  • 本地算法与本地占位图不得被描述为 AI 模型生成。

5.3 错误分类

所有失败统一归入：配置错误、鉴权失败、网络不可达、限流、超时、服务端错误、本地写入失败、产物不完整。界面按分类给出一句可执行的下一步，而不是原始报错堆栈。

5.4 结果契约

两种模式输出同一结构：主图地址、来源标识、分层列表（含每层用途与顺序）、清单地址、生成参数快照。下游页面只依赖该契约。
