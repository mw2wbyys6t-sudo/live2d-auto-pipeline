# 原生桌宠部署联调记录

## 本轮已实现

- Go 部署接口执行独立真实 GPU 像素与参数形变验收，通过后启动原生桌宠。
- 桌宠完成首帧交换后才发出就绪消息；服务端收到后才返回已部署。
- 使用模型包 SHA-256 比对验收与加载时的文件，修改后拒绝启动。这是修改检测，不是针对恶意并发写入的原子快照保护。
- 新增 GET /api/deploy/desktop/status。进程退出后返回 stopped，禁止重复部署开启第二个窗口。
- Windows 虚拟环境启动器 PID 与实际 Python PID 可能不同，已通过真实联调发现并修正；超时清理覆盖子进程树。
- 原生桌宠参数设置移到模型 Update 之后，避免被自动更新覆盖。
- 补齐旧 Go 测试引用的三个缺失辅助函数，并将角色编号校验接入读取、保存、删除，阻止路径穿越。

## 本轮实测

- Python 单元测试：110 通过，1 项单色聚类警告。
- Python 真实 GPU 集成：3 通过，包括有效像素/参数形变、首帧握手/8 帧正常退出、指纹不匹配拒绝。
- Go 全包测试：通过。默认跳过需要显式启用的真实桌面测试。
- Go 编译：通过。
- 单独启用真实 HTTP 集成：通过。实际执行 HTTP 请求、GPU 验收、透明原生桌宠首帧、重复启动拒绝、终止测试桌宠后查询 stopped。

测试输入仍为官方 Haru 模型，不是本系统从素材新编译的 moc3。测试结束已关闭测试进程。

## 尚未完成，不应宣称完成

1. 素材自动创建 Cubism 工程、绑定、导出新 moc3：没有实现。再次核实官方外部 API，不能据此断言它具备工程创建和编译能力。需要可验证的编辑器自动化通道或正式编译接口。
2. 桌面透明仍是 Windows 色键透明，非逐像素 alpha；桌面合成视觉尚未验收。
3. 完整前端导出页面到桌宠启动尚未联调。本轮验证的是服务端 HTTP 链路。
4. 进程状态只在当前服务进程生命周期内维护，不提供服务重启后的进程接管。
5. 仅针对本机 Windows 交互桌面；不是容器或远端云服务器上的桌面部署。

官方 API 资料：https://docs.live2d.com/en/cubism-editor-manual/external-application-integration-api/
