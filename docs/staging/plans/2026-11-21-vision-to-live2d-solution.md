# 单张立绘到高质量 Live2D 模型：现状研究与解决方案

date: 2026-11-21
status: 阶段 0 实施中
source_branch: feat/forearm-elbow

## 决策摘要

目标是把单张人物立绘转为可审计、可编辑、可驱动的二维 Live2D 模型。建议沿用当前模块化流水线，优先补齐真实素材质量评测、交互式纠错和最终运行时验收，再按部件逐步改善分割、遮挡补全、网格和绑定。暂不建议整体重写，也不建议用更密的网格或更多自动生成层数作为质量代理。

“像素锚定”应解释为：每个输出图层像素可以追溯到源图坐标、源掩码或有明确标记的补全来源；动画由 ArtMesh 顶点、变形器和参数驱动，而不是逐像素单独建立一个自由运动点。单张正面静态图无法唯一确定遮挡区域的真实外观、深度、三维姿态或未绘制动作。对无法从输入证实的信息，系统应请求用户修正、保留缺件，或明确标为推断，不能自动宣称真人级。

## 当前项目事实

当前仓库位于 `feat/forearm-elbow`，HEAD 为 `40c3cac`，父提交包含已合并的腿部关节与挥手/走路动作。工作树存在用户未提交修改：`.fossa.yml`、`.github/workflows/ci.yml`、`.github/workflows/tauri-build.yml`、`.gitignore`、`desktop/Cargo.lock`；本方案不覆盖这些文件。

项目已具备以下基础：

- Python 工作流负责图像规范化、语义分割/启发式回退、图层合成、质量记录及 Rigging 编排。
- 分割侧已有 GroundingDINO/SAM2、部件拆分、遮挡补全和 manifest 来源/置信度记录；真实立绘上的泛化质量仍需系统化量测。
- Rigging 已有图层命名、PSD/manifest、ArtMesh 网格、UV/图集、骨骼权重、旋转/warp 变形器、参数键形、动作与 MOC3 导出。
- 已有 `exportable`、`rig_ready`、`quality_ready` 区分、变形压力闸门、死参数探针及 Cubism 运行时验收入口。
- Rust `native/split_kernel` 目前是可选纯函数加速层，不是分割模型；Python 保留模型推理和编排。Rust/C++ 面捕属于独立输入控制，不会自动提高立绘分层质量。

当前主要缺口：

- 仓库单测通过不等于真实权重、真实素材或 Cubism 运行时视觉结果通过；部分渲染级检查受环境限制。
- PixelGridMesher 存在，但主导出仍主要使用组合网格路径；像素覆盖检查器与主导出的一致性闸门尚未完全贯通。
- 自动识别候选与最终“可独立动画部件”之间仍需要质量判定及低置信度人工修正流程。
- 单图遮挡补全、左右判断、服装/身体交叠与长发细分存在信息不足或风格依赖，不能对所有素材承诺全自动正确。
- 动作文件存在不代表动作自然；动作应按部件拓扑、关节连接、遮挡和安全范围评估。

## 外部技术证据

- SAM 2 定义为可提示的图像/视频分割方法，支持点、框、掩码等提示并可交互迭代修正；它输出的是对象掩码，不会自动决定 Live2D 部件语义、遮挡补绘和变形绑定。[cite:1]
- Grounding DINO 的贡献是开放集、文本条件目标检测，适合作为候选定位手段；检测框不是像素级部件真值，仍需分割与结构校验。[cite:2]
- Live2D 将 PSD 层映射为 ArtMesh，使用网格顶点变形图像；官方文档也说明过细网格会增加数据量，网格应按变形需求设计。[cite:3]
- Cubism 网格自动生成提供内外点间距、边界余量、边界点数量和透明阈值等控制，且生成网格后仍可编辑。这支持“按部件/变形需求配置网格”而非“每像素自由点”。[cite:4]
- Live2D 的嵌入式导出物包含 MOC3、model3.json、纹理以及可选 physics3.json、motion3.json 等；因此最终通过条件必须检查运行时关联资源和实际模型行为，而不止看中间 PNG 或 JSON 生成成功。[cite:5]
- 单目人体三维姿态估计存在深度歧义和遮挡导致的病态性；单张图的二维观察通常不足以唯一恢复三维姿态。[cite:6]

这些证据支持“提示式识别 + 可修正分割 + 来源可追溯 + 部件级网格/绑定 + 真实运行时验收”的组合方案。它们不证明当前模型在项目数据上的准确率；项目必须用自有授权素材建立基准集后再量测。

## 架构决策

**决策状态：**采用方案 B；阶段 0 先建立授权素材基准和验收闭环。首阶段同时支持 PNG 与 PSD，具体责任边界见阶段 0。

**目标：**从一张立绘生成可导入、可编辑、可驱动的分层模型；每个自动产物可追溯；关键错误能在进入导出前被发现。

**非目标：**从一张静态图保证恢复真实三维结构；自动创造输入中不存在的服装、表情、肢体或动作细节；承诺所有画风均无需人工介入；让每个源像素成为独立控制点。

| 方案 | 决定 | 理由 |
|---|---|---|
| A：继续扩充规则与名称映射 | 不作为主方向 | 覆盖面增加不代表语义正确，容易将未知结构映射为 ready |
| B：沿用模块化流水线，统一部件证据/像素来源契约，加入交互修正和分级验收 | 推荐 | 贴合现有 manifest、PSD、Rigging 与测试结构；可按阶段回退 |
| C：重写为单一端到端模型 | 暂缓 | 训练数据、质量基准和运行时输出契约尚未证明足够；整体重写扩大回归面 |
| D：完全人工逐层标注 | 作为低置信度回退 | 质量可控但无法满足大部分自动化目标 |

**正面影响：**有来源证据和质量状态后，自动结果可追踪；低置信度部件不会伪装成完成；局部模块可替换而不重写整个链路。

**负面影响：**前期需要建立有授权的代表性素材基准和人工复核标准；复杂输入仍可能阻断自动 ready；更严格的闸门可能降低一次性自动成功率，但能避免导出后才发现错误。

**可逆性：**两向门。优先增加版本化 manifest 字段、质量报告和独立闸门；任何影响旧格式的字段需保留兼容读取。只有基准数据证明现有边界无法达标时，才考虑替换识别或网格模块。

## 系统边界与数据流

```text
源图/源 PSD
  -> 输入校验与坐标归一
  -> 人物/姿态/候选部件检测
  -> 部件 mask（自动提示 + 人工点/框/笔刷纠错）
  -> 部件语义、左右侧、遮挡关系与来源证据
  -> 遮挡补全（仅在授权且证据/策略允许时）
  -> 图层、命名、PSD 与 manifest
  -> 面向变形用途生成 ArtMesh / atlas / deformers / parameters
  -> 动作曲线与物理设置
  -> MOC3/模型资源导出
  -> 官方运行时加载、参数扫动、渲染差分与人工视觉签核
```

| 上下文 | 职责与模型 | 上游/下游关系 | 失败行为 |
|---|---|---|---|
| 输入与来源记录 | 源图坐标、PSD 结构、授权/哈希和变换记录；由现有 Python 工作流承接 | 上游文件；下游识别与所有产物 | 无法读取或坐标不一致时阻断处理，不覆盖源文件 |
| 视觉候选与掩码 | 产生检测框、类别、mask、置信度和人工编辑；GroundingDINO/SAM2 等作为可替换适配器 | 上游输入；下游部件契约 | 低置信度保留候选并要求确认；不伪造缺件 |
| 部件语义与分层 | 稳定部件 ID、左右侧、父子关系、draw order、mask 来源、补全状态；对应 PART_SPECS/manifest/PSD | 接收 mask，向网格与 Rigging 提供规范化部件 | 契约冲突或守恒失败则阶段非 ready |
| 网格与形变 | 将部件纹理绑定至 ArtMesh 顶点、旋转/warp 变形器和参数键形 | 输入分层契约；输出模型几何与绑定 | 自交、越界、漏覆盖或安全动作露洞时阻断相应质量等级 |
| 动作与运行时验收 | 参数曲线、动作、physics、SDK 加载和渲染对照 | 依赖已绑定模型；反馈问题给绑定/分层 | 缺参数跳过动作组；运行时不兼容不标记发布就绪 |

**依赖方向：**模型适配器只输出统一候选结构；拆分和补绘逻辑不得直接写入最终 PSD；导出器消费版本化 manifest，不反向改变识别结果。Rust 可优化经 profiling 证明的纯数组热点，不能承载或复制 Python 的模型决策规则。面捕输出驱动信号，不负责生成部件 mask 或动作语义。

**交互方式：**本地同步任务适合单张图的即时预览；耗时批处理应沿用现有任务/进度状态，失败可恢复，不通过高频轮询完整图像数据。图像及模型权重不上传外部服务，除非用户明确授权。

## 统一部件/像素契约

每层至少具有：`layer_id`、`part_id`、`side`、`parent_id`、`draw_order`、`canvas_transform`、`mask_source`、`source_image_hash`、`provenance`、`confidence`、`completion_method`、`occlusion_links`、`mesh_ref`、`status`。字段应在现有 manifest 基础上版本化增量扩展，不另建冲突的第二权威表。

状态沿用现有 readiness 概念并细化阶段：`detected`、`derived`、`manual_required`、`missing`、`ready_for_rigging`、`exportable`、`rig_ready`、`quality_ready`。状态只能由对应阶段校验推进；模型导出成功不得自动升级为 quality_ready。

像素追溯要求：

- 纯拆分子层的 mask 并集等于母层 mask，且非声明重叠互斥。
- 补绘像素单独记录来源与范围；源图像素与补绘像素不能混淆。
- 所有层记录源画布坐标变换；拼图集 UV 必须能反算到纹理区域。
- 网格按轮廓、细节和预期变形密度分配顶点；不采用每像素一个自由顶点。
- 每个核心部件拥有静止重建检查和动作压力检查；风险结果可定位回层、网格或变形器。

## 分阶段实施方案

### 阶段 0：基准与验收闭环

首阶段同时纳入 PNG 与 PSD，但评测职责不同：PNG 是单图识别、拆分、像素来源追溯、透明度/重建、PSD 生成及后续绑定输入的主视觉基准；PSD 是已有图层结构读取与往返保真的结构基准，覆盖组路径、图层名、画布坐标、绘制顺序和可见性，不承诺复杂混合模式、剪贴蒙版等特性完整保真。每个真实样本必须登记权利人/来源、许可标识与证据位置、用途授权、再分发状态、原始文件 SHA-256、标注版本和样本类别；信息不全即 BLOCKED，不进入基准统计。真实素材默认本地或私有存储，不把敏感或第三方受限素材提交到 GitHub；对外上传前必须取得用户明确同意。

可公开测试先用不含真实人物内容的合成 PNG 和程序生成/模拟 PSD 结构 fixture。真实视觉样本按清晰正面、侧身、遮挡、宽松服装、长发、低分辨率、非对称姿势分层。真人感首批人工视觉签核为头部转向、闭眼/张嘴、抬臂与肘关节、走步；完整压力范围另含躯干摆动及头发/衣摆二级摆动，物理二级摆动优先级低于核心面部与姿态。先复用现有 `rig_acceptance.py`、`rig_visual_gate.py`、`deform_stress_gate.py`，将失败分类为识别、拆分、补全、命名、网格、绑定或运行时问题；缺官方运行时或素材授权证据时保持 BLOCKED。

通过条件：PNG 与 PSD 各有可重现的基准条目和职责说明；每个样本可校验哈希与授权状态；无许可证据的真实样本被阻断；合成 fixture 测试可在 CI 运行；动作清单、指标、人工签核记录和失败分类明确。

### 阶段 1：交互式视觉分割与纠错

在工作台提供基于点/框/笔刷的部件 mask 修正，显示候选类别、置信度、前后层和来源；变更可撤销并保存在项目级标注数据。模型只提出候选，用户确认后才把低置信度区域升级。增加多候选比较和局部重分割，不要求整张重跑。

通过条件：用户能修正一个部件而不破坏其他 mask；每次修改后拆分守恒、坐标对齐和来源追溯检查均通过；修正历史可恢复。

### 阶段 2：部件语义、遮挡与补绘

将标准人体与服装部件统一到一个版本化契约。针对左右侧、前后关系、关节边界和必需槽位建立显式状态。遮挡补全先支持可解释、受限的规则和人工绘制；生成式补全作为可选路径，必须标记生成区域、工具/方法、置信度和用户确认状态。不可证实的结构保持 `manual_required` 或 `missing`。

通过条件：无错误侧绑定；父子关系无环；draw order 一致；纯拆分守恒；补绘来源可见；未知深度不会自动被推断为确定值。

### 阶段 3：部件感知网格与绑定

按部件类别制定网格策略：脸部五官保留局部高密度；长发束和衣物边缘保证轮廓支撑；躯干和肢体关节区域根据变形压力增加内部顶点；静态小配件控制顶点数。先验证现有组合网格主路径与 PixelGridMesher 的适用范围，再决定合并还是保留不同策略。把 atlas consistency 校验接入每次正式导出。

绑定顺序按父级到子级：身体/头部主控制、肩髋、肘膝、手脚/发束/衣摆等局部控制，再配置物理。参数只声明在确实存在对应几何和纹理的模型上；缺层时不生成空转参数。

通过条件：静止重建对齐；网格覆盖有效纹理；UV 往返误差在设定容差内；关节安全范围内无透明洞、拉伸越界或错误部件联动；模型复杂度不超过项目设定预算（预算需由真实目标设备测量后定值）。

### 阶段 4：复杂动作与实时输入

先建立动作目录和参数契约，再扩展动作曲线：头部转向/倾斜、眨眼与口型、躯干摆动、双肩与肘、髋膝步态、发束/衣摆二级摆动。自动动作与面捕输入共享同一参数空间，但面捕映射可校准、限幅、平滑，并可被动作覆盖规则仲裁。自动生成动作必须以参数可用性为前提，不能对缺少部件的模型伪称支持。

“真人感”在产品中定义为二维角色动作的自然度与连贯性，不定义为真人动作捕捉精度。单张立绘可支持已有像素上的形变；复杂转身、背面、未画出的手势或表情需要额外素材、多视图或人工补绘。

通过条件：动作库逐项验证参数覆盖、关节连续性、遮挡顺序、循环接缝、脸部表情与肢体动作冲突；输入噪声下无明显抖动；无效参数和不支持动作有明确反馈。

### 阶段 5：端到端发布闸门

对每次候选模型运行结构检查、MOC3/资源关联检查、Cubism Core 或官方 SDK 加载检查、关键参数扫描、代表性姿势渲染、差分及人工视觉签核。检查器不可用时状态为“未验证”，不能当作通过。保持旧流水线可选，按素材集逐批对照后再切换默认路径。

通过条件：分层、manifest、PSD、纹理、UV、绑定与模型资源相互一致；全部必需动作在实际运行时可观察；质量报告列明自动通过项、人工确认项和剩余风险。

## 验收指标与质量闸门

数值门槛必须先用授权基准集校准；在基准完成前不编造准确率或延迟目标。

| 属性 | 指标/规则 | 来源与频率 | 失败处理 |
|---|---|---|---|
| 像素来源可信 | 所有输出 alpha 像素归属源 mask、声明重叠或有 provenance 的补绘；未归属像素为 0 | 图层重建与来源校验；每次导出 | 阻断 `quality_ready` |
| 拆分守恒 | 纯拆分母 mask 与子 mask 并集完全一致；未声明重叠为 0 | 单测与真实样本报告；每次分层 | 阻断对应部件 |
| 语义/左右准确 | 每个 P0 槽位经标注基准和人工审核；错侧为 0 | 基准集评估；模型/规则改动时 | 回退到人工确认 |
| 网格覆盖与 UV | 网格有效、纹理覆盖完整、UV/图集坐标往返在校准容差内 | atlas consistency 和导出检查；每次导出 | 阻断模型导出或标记未验证 |
| 形变安全 | 关键动作安全区内空洞为 0，越界区域明确报告 | deform stress gate；绑定/网格改动时 | 缩小动作安全区或返工 |
| 参数有效 | 关键参数扫动时目标部件发生可测变化，非目标部件变化在预期范围 | 死参数探针/差分渲染；每次模型验收 | 阻断该参数/动作组 |
| 运行时可加载 | 目标运行时加载模型和必需资源成功 | Cubism Core/SDK smoke test；每个候选构建 | 不标记可发布 |
| 性能与体积 | 推理时延、导出时延、模型/图集大小、目标帧率按目标硬件实测设预算 | 基准机 profiling；发布候选及重大变更 | 调整模型、网格或执行路径 |

## 风险与缓解

| 风险 | 可能性/影响 | 缓解 |
|---|---|---|
| 单图遮挡与深度不可辨识 | 高/高 | 保留未知状态；提供局部人工修正和补绘；不自动伪造完整身体 |
| 动漫风格与真实人体模型域差异 | 高/高 | 用授权动漫立绘建立分层评测集；检测器只作候选；报告按部件/画风切片 |
| 自动生成补绘风格漂移 | 中/高 | 生成区域 provenance、用户预览/确认、局部撤销；默认不覆盖源图 |
| 网格过密导致性能和资源膨胀 | 中/中 | 按变形需求分配顶点并统计体积/帧率；对比质量收益后才提高密度 |
| PNG/PSD/manifest/atlas 产生坐标或顺序不一致 | 中/高 | 单一 manifest 权威、版本化 schema、往返验证、导出一致性闸门 |
| 本地模型权重/素材隐私与许可 | 中/高 | 本地处理优先；数据集登记来源和许可；任何外部上传前询问用户 |
| GPU/官方运行时不可用造成假绿 | 中/高 | unavailable 标为未验证；独立 CI job/本机 smoke test，不把跳过当通过 |
| 原生内核扩展造成逻辑分叉 | 中/中 | 仅加速纯函数；保持 Python 参考实现；逐字节差分与可关闭回退 |

## 已确认的阶段边界

1. 首阶段同时覆盖 PNG 和 PSD：PNG 承担视觉拆分与下游输入基准；PSD 承担已有结构读取/往返基准。复杂 PSD 特性另行声明，不纳入首阶段完整保真承诺。
2. 真人感首批人工视觉签核为头部转向、闭眼/张嘴、抬臂与肘关节、走步；压力范围扩展到躯干摆动、头发/衣摆二级摆动。
3. 真实视觉基准只收录有清晰权利与用途授权的素材。当前没有已核实的人物基准素材；阶段 0 先建立合成 fixture 和授权登记契约，真实样本需由用户提供并确认许可后加入。指标数值与目标硬件预算由样本实测校准。

## 责任、成本与复核条件

- 责任：用户确认产品范围与素材许可；本地流水线测试负责契约和回归；工作台人工验证负责视觉签核。具体模块负责人在实施计划中指定。
- 临界依赖：分割模型可替换，需保留模型版本、权重来源、运行配置和 CPU/现有后端回退；GPU/Cubism 运行时不可用时报告未验证，不伪造成功。
- 回退：保持现有默认流程；新交互、网格策略和质量闸门按配置逐阶段启用；manifest/schema 增量版本化。
- 复核触发：授权基准显示某部件长期不稳定；人工修正成本没有下降；运行时质量比现有模型退化；或目标硬件预算无法满足时，重新评估识别器、网格策略或阶段范围。
